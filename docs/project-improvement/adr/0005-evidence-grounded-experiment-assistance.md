# ADR-0005: 측정 근거를 바탕으로 한 AI 가설·실험 제안의 단계적 검토

## 상태

방향 승인 / AI·RAG 구현 보류. #200은 실제 대비 실험을 먼저 구성한다.

## 맥락과 재현 근거

현재 read-only MCP는 허용된 summary·manifest와 재고 불변식을 조회하고, 조건이 부족하면 비교를 거절한다. 이는 도구 인터페이스 구현이며 LLM의 분석 품질이나 사용자 효용을 입증한 결과는 아니다.

#198에서 높은 호스트 CPU peak가 관측됐지만 JVM·MariaDB 단독 병목으로 귀속하지 못했다. 정상 좌석 충돌 409, DB 잠금 대기, pool 압력, 계측 부담은 서로 다른 현상이다. 원인을 확인하지 않고 인프라나 부하를 확대할 수 없다는 판단은 ADR-0004를 따른다.

AI의 후보 역할은 측정 근거를 찾아 병목 **가설**과 이를 구분할 **다음 실험**을 제안하는 것이다. 선택 불가 좌석의 설명만 제공하는 챗봇은 현재 화면의 상태 안내와 중복되고 효용 근거가 부족해 우선하지 않는다.

## 결정

1. 우선 사람이 검토할 수 있는 실험 조건·결과를 확보한다. #200은 가상 20석, 20 iterations/s, 인기 요청 70%, Hold 500ms, seed 17을 고정하고 인기 1석/10석을 교차 반복한다. 정상 충돌과 시스템 대기를 구분하는 근거이지 서비스 처리 한계 측정은 아니다.
2. AI 도입 후보는 MCP의 검증된 구조화 지표를 조회하고, 관련 ADR·버전별 실험 조건을 근거로 가설·누락 계측·후속 실험을 제안하는 보조 흐름이다. 원인 확정은 재실험으로 수행한다.
3. 숫자·완료 여부·재고 검증은 기존 코드가 계산한다. AI 출력에는 관측 사실, 가설, 근거 ID, 반증 가능한 검증 계획을 구분한다. 조건이 다른 run을 개선 전후로 비교하지 않는다.
4. RAG는 자료 증가로 기존 고정 조회/검색에 실제 한계가 생겼을 때 검토한다. 최신·관련 버전의 ADR과 문서 근거 검색에 사용하고 현재 예약 상태·수치 계산을 vector 검색에 맡기지 않는다.
5. LLM·Spring AI·LangChain·LangGraph는 이번 Issue에서 도입하지 않는다. 실험 실행, RPS 증량, DB 변경, 결제·예약 확정은 AI에 자동 위임하지 않는다. 기존 read-only MCP의 권한도 확대하지 않는다.

## 검토한 대안

- 사람 + 기존 runner/MCP — 현재 규모에 적합한 기준 방식. 동일한 근거로 충분히 다음 실험을 선택할 수 있다면 유지한다.
- 문서 RAG와 상태 조회 챗봇 — 사용자 문제가 분명하지 않아 보류.
- AI 실험 보조 — 반복 근거 조회와 조건 비교 부담이 생길 때 후보. 정확도·비용·지연·권한 경계 검증이 추가로 필요하다.
- 자율 부하 확대/인프라 변경 — 원인 미확정과 실행 영향 때문에 채택하지 않는다.

## 결과와 trade-off

부하 실험의 가치와 AI 기술 사용을 구분한다. 현재 단계에서 AI 도입 성과나 분석 비용 절감을 주장하지 않는다. 향후 AI를 도입하면 알려진 원인 fixture와 근거 부족 fixture에서 검색 정확도, 출처 일치, 근거 없는 단정, 비교 불가 조건 거절, 실행 가능한 제안, 응답 지연·토큰 비용을 평가한다. LLM을 평가자로 쓰더라도 고정된 기대 근거·사람 검토를 함께 사용한다.

## 적용 범위와 한계

가상 좌석의 로컬 개발·실험 분석에 한정한다. 실제 운영 장애 해결, 실제 공연장 처리 용량, 실 PG 검증을 의미하지 않는다. 정상 좌석 충돌의 증가 자체를 서버 병목으로 판단하지 않는다. 인기 집합 변경은 성공/409 비율뿐 아니라 성공 시 DELETE 호출량도 바꾸므로 혼합 p95나 전체 HTTP RPS만으로 성능 개선을 주장하지 않는다.

## 재검토 조건

- 반복 실험의 근거 조회·조건 비교·다음 실험 선택에 실제 비용이나 오류가 기록됨
- 정답/기대 근거가 정의된 평가 사례를 확보함
- 기존 조회 방식 대비 AI/RAG가 도움을 주는지를 비교할 수 있음
- 모델 호출 예산, 자료 접근 범위와 실행 승인 경계를 정의함
